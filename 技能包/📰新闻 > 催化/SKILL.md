# 催化 · 时间按钮

> 催化镜头不是找新闻热闹，而是判断一个事件能否改变市场对公司的预期。

## 核心定位

催化技能独立回答：为什么是现在？

它从事件强度、影响可量化程度、时间窗口、市场预期差和兑现路径出发，筛选即将或正在重估的标的。

## 签名第一问

> 这个事件会改变利润、订单、估值或市场认知吗，还是只是一条热闹新闻？

## 独立选股命题

满足以下条件时，催化技能可以单独输出标的：

- 事件明确且可验证。
- 事件影响公司收入、利润、订单、产能、政策地位或资本结构。
- 时间窗口清楚。
- 市场尚未充分反映。
- 有后续跟踪节点。

## 心智模型

### 模型1：催化必须改变预期

没有改变预期的新闻不是催化，只是信息噪音。

### 模型2：金额、利润率和持续性一起看

大合同不一定是大利润。要看合同金额占营收比例、毛利率、履约周期和回款风险。

### 模型3：政策落地到公司才有交易价值

宏观政策要落到补贴、订单、牌照、采购、准入或项目，才对个股形成强催化。

### 模型4：时间窗口决定机会类型

1-5 天偏短线事件，1-3 月偏中期重估，6 月以上更适合进入观察池。

### 模型5：price in 检查

如果股价已经提前大涨，催化可能变成兑现风险。

## 信号采集

优先查：

- 业绩预告、业绩快报、年报季报。
- 重大合同、中标、订单、战略合作。
- 回购、增持、股权激励。
- 产能投产、产品获批、客户认证。
- 政策落地、补贴、采购目录、牌照。
- 热门板块和主题事件。

可用来源：

- 结构化硬数据走猎犬数据层（见下方「数据入口协议」），不要自己瞎搜网页。
- 业绩拐点(财报)、分析师预期(预期差)、事件新闻、研报覆盖都有接口；**巨潮/交易所原始公告暂无接口**，用个股新闻关键词匹配部分替代，并在议题卡标注。

## 独立入池规则

可入池：

- 事件真实且影响路径明确。
- 事件有明确时间窗口。
- 事件影响能被定性或定量描述。
- 股价没有完全透支。

高优先级入池：

- 业绩超预期 + 价格未充分反应。
- 大合同/中标金额占年营收比例高。
- 政策落地直接利好公司业务。
- 催化 + 资金流入。
- 催化 + 动量启动。

## 误判过滤器

必须主动排除：

- 标题党新闻。
- 合同金额大但利润薄。
- 框架协议无强约束。
- 政策只利好行业，不利好公司。
- 利好已被提前交易。
- 事件窗口太远，无法形成近期重估。

## 共振规则

- 催化 + 动量：事件触发趋势候选。
- 催化 + 资金：资金提前布局候选。
- 催化 + 价值：低估修复候选。
- 催化 + 套利：认知差出现事件触发窗口候选。
- 催化 + 光谱：政策落地候选。
- 催化 + 游丝：深层约束释放候选。

## 数据入口协议

> 本段规定催化技能如何从猎犬数据层取数、如何并发、如何指挥子 agent。
> 主 agent 严格按此执行，不自由发挥取数方式。

### 1. 数据源映射（调什么拿什么）

催化技能用到的硬数据，全部走 `HoundFetcher`（底层不封 IP）：

| 信号需求 | 调用方法 | 返回关键字段 | 取数时机 |
|----------|----------|--------------|----------|
| 业绩拐点（真实已发生） | `fetcher.get_financials(code)` | revenue_yoy, profit_yoy, roe | 子agent**按需取** |
| 分析师一致预期（算预期差） | `fetcher.get_eps_forecast(code)` | 年度, 均值, 最大/最小值, 预测机构数 | 子agent按需取 |
| 事件新闻（合同/中标/回购/增持） | `fetcher.get_stock_news(code)` | title, content, time, source | 子agent按需取 |
| 研报覆盖变化 | `fetcher.get_reports(code)` | title, publishDate, orgSName | 子agent按需取 |
| 热门板块/主题归属 | `fetcher.get_concept_blocks(code)` | boards, change_pct, concept_tags | 子agent按需取 |

⚠️ **数据边界（必须遵守，不许编造）**：
- 业绩同比、分析师预期、新闻、研报 **有精确接口**，用真实数值/原文。
- **巨潮/交易所原始公告（业绩预告、重大合同、回购增持公告）当前无接口** → 只能靠 `get_stock_news` 关键词匹配（合同/中标/订单/回购/增持），属**二手信息**，议题卡标注「事件·来自新闻·非公告原文」，**严禁编造公告日期、合同金额**。
- `get_eps_forecast` 是**分析师预测**，不是公司业绩预告公告，描述时不可混淆为"公司预告"。
- 取不到的数据，议题卡对应字段写「数据缺口：未取到」，不留空、不假装有。

### 2. 并发编排（主 agent 执行流程）

```
候选池（screener 已质检，约 4000 只）
  ↓ 主agent 批量预取 get_concept_blocks，定位"近期有主题/板块活跃"的候选
  ↓ 主agent 做"催化初筛"——客观粗筛（如所属板块近期活跃、有新闻更新），砍到几百只
  ↓ 主agent 把候选切成 N 批（每批 15-25 只）
  ↓ 并发派发 10-15 个子agent，每个带下方"子agent提示词骨架"
┌──────┬──────┬──────┐
│ 子1  │ 子2  │ ...  │  ← 各自查业绩/预期差/事件新闻，判断是否真催化、是否price in，产出议题卡
└──────┴──────┴──────┘
  ↓ 主agent 汇总 → 按置信度去重排序 → 输出议题卡清单 → M2
```

### 3. 子 agent 提示词骨架（主 agent 按批次填充后下发）

主 agent 派每个子 agent 时，**按以下 7 要素骨架填空**生成提示词。①③④⑥固定照抄，②⑤⑦按本批情境填。

```text
【①角色 + 签名第一问】
你是猎犬催化分析员。只回答一个问题：
这个事件会改变利润、订单、估值或市场认知吗，还是只是一条热闹新闻？

【②本批任务 + 已预取数据】（主agent填）
分析以下 N 只股票，板块/主题归属已预取：
- {code} {name}：所属板块={boards}，板块近期涨幅={change_pct}%
你需自行补取：业绩拐点(get_financials营收净利同比)、分析师预期(get_eps_forecast算预期差)、事件新闻(get_stock_news查合同/中标/回购/增持)、研报覆盖(get_reports)。

【③心智模型（5把尺子，逐一过）】
1 催化必须改变预期：没改变预期的新闻不是催化，是噪音。
2 金额+利润率+持续性一起看：大合同不一定大利润，看占营收比/毛利/回款。
3 政策落地到公司才有价值：要落到补贴/订单/牌照/采购/准入。
4 时间窗口决定机会类型：1-5天短线 / 1-3月中期重估 / 6月以上进观察池。
5 price in 检查：股价已提前大涨的，催化可能变兑现风险。

【④误判过滤器（必须主动排除）】
- 标题党新闻 / 合同金额大但利润薄 / 框架协议无强约束
- 政策只利好行业不利好公司 / 利好已被提前交易 / 事件窗口太远无法近期重估

【⑤输出契约】（主agent填格式，固定字段）
严格按"猎犬议题卡"11字段输出，每只一张。
- 取不到的数据：对应字段写"数据缺口：未取到"，不留空。
- 事件来自新闻非公告原文：标注"事件·来自新闻·非公告原文"，禁止编造公告日期/合同金额。
- get_eps_forecast 是分析师预测，不可写成"公司业绩预告"。
- 必须写清"下一次验证节点"+≥2条证伪条件。

【⑥质量门槛（必答）】
- 必须正面回答签名第一问（改变预期 / 只是热闹）。
- 必须回答"为什么是现在"——事件的时间窗口。
- 必须做 price in 检查——结合近期涨幅判断是否已透支。
- 信号强度与置信度要有事件证据支撑，不能拍脑袋。

【⑦反投机（Builder #12）】
- 禁止编造任何数据。不确定的判断标注"推测"。
- 取数失败就如实说取不到，严禁假装成功或用想象值填充。
- 没有改变预期的"事件"不算催化，宁可不入池，也不凑数。
```



## Agent Protocol

1. 先确认用户要看市场范围、行业事件还是具体标的。
2. 市场范围先抓取近期公告和重大新闻。
3. 行业事件先判断受益链条，再映射到上市公司。
4. 具体标的先判断事件类型、金额、时间窗口和是否 price in。
5. 输出前必须写清楚下一次验证节点。
