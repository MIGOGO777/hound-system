# 游丝 · 跨行业深层约束挖掘框架

> 游丝不是寻找热门行业里的龙头，而是沿着需求增量向下钻，寻找那些隐藏在价值链深处、扩张最慢、替代最难、定价权最可能被低估的关键约束节点。

---

## 核心定位

| 维度 | 定义 |
|------|------|
| **认知操作类型** | 跨行业价值链逆向工程 + 深层约束识别 |
| **签名第一问** | 需求往哪流？价值链哪里最难扩张、最难替代、最容易被忽视？ |
| **主要输出** | 深层约束节点、控制者、证据链、错配程度、证伪条件 |
| **适用范围** | 制造、能源、医药、军工、消费、农业、金融、互联网、低空经济、AI/半导体等 |
| **不适用场景** | 纯情绪交易、短线盘口博弈、无法拆出价值链的概念炒作 |

### 与其他猎犬技能的分工

| 技能 | 问题 |
|------|------|
| **光谱** | 哪个方向正在被政策、周期、技术、资金照亮？ |
| **游丝** | 这个方向真正卡在哪里？谁控制最深、最难替代的节点？ |
| **动量** | 市场什么时候开始承认这个节点？ |
| **价值** | 当前价格是否给了足够安全边际？ |
| **资金** | 资金是否正在进入或离开这个约束节点？ |
| **催化** | 什么事件会让错配被市场重新定价？ |

## 深层约束六分法

分析时不要只找“物理瓶颈”。任何让价值链扩张变慢、替代变难、利润分配不均的因素，都可能是游丝。

| 约束类型 | 识别问题 | 常见信号 | 示例 |
|----------|----------|----------|------|
| **物理约束** | 有没有材料、设备、产能、良率、地理位置限制？ | 扩产周期长、良率爬坡慢、资源稀缺、设备单源 | 变压器、InP衬底、特种气体、冷链仓 |
| **时间约束** | 有没有认证、导入、临床、建设周期，无法用钱快速压缩？ | 认证超过12个月、客户导入慢、项目交付排队 | 车规认证、医药临床、军工定型、并网周期 |
| **牌照约束** | 有没有监管许可、准入资质、经营牌照？ | 牌照数量有限、审批节奏慢、地方/行业准入 | 金融牌照、空域审批、医疗器械注册证 |
| **信任约束** | 客户是否因为风险太高而不愿轻易替换供应商？ | 历史交付、客户黏性、供应稳定性、品牌背书 | B端核心供应商、医院渠道、军工配套 |
| **网络约束** | 是否控制渠道、接口、标准、节点或生态位置？ | 接入成本高、网络越大越强、替代需要整体迁移 | 交易接口、物流网络、支付清算、产业标准 |
| **认知约束** | 市场是否还没意识到这个小环节的重要性？ | 财报占比小、名字不性感、行业报告很少覆盖 | 耗材、检测、辅料、代工小环节 |

### 判断优先级

优先找同时满足三项的节点：

1. **需求增量明确**：上游或下游正在被新需求拉动。
2. **扩张速度慢**：产能、认证、牌照、信任或网络不能快速复制。
3. **市场注意力低**：主流叙事还在看龙头、整机、平台或终端品牌。

## 数据入口协议（SearXNG 路线）

> 游丝和光谱一样是**搜索驱动**技能，不走结构化 fetcher（行情/财报对"价值链约束"基本没用）。
> 主 agent 通过 **SearXNG HTTP API** 搜索一手资料，沿价值链逐层下钻，再并发派子 agent 深挖。
> 本段规定怎么搜、怎么并发、怎么指挥子 agent，主 agent 严格按此执行。

### 1. SearXNG API（本机部署，实时元搜索）

| 端点 | 用途 | 关键参数 |
|------|------|----------|
| `http://localhost:4000/search` | 搜索资料 | `q`、`format=json`、`language=zh-CN`、`time_range`、`categories` |

- `q`：搜索关键词（必填）
- `format=json`：返回 JSON（必填）
- `language=zh-CN`：中文优先
- `time_range`：`day`/`week`/`month`/`year`。⚠️ **默认不加**。SearXNG 的时间过滤依赖各引擎自报 `publishedDate`，大量中文页面不返回日期会被一刀切光（实测同一查询带 `time_range` 返回 0 条、去掉返回 10+ 条）。约束/扩产/份额这类结构性信息本就变化慢，**不需要时间过滤**；只有明确要"最近一周新闻"时才加。
- 返回 `results[]`，每项含 `title`、`url`、`content`(摘要)、`score`、`publishedDate`

⚠️ **首轮空结果 ≠ 无数据，必须重试（实测踩过坑）**：
- SearXNG 背后聚合 Google/Bing 等免费引擎，会间歇性限流/超时，**同一查询可能这次 0 条、下次 19 条**。
- 空结果时按顺序重试：① 先去掉 `time_range`；② 再减少关键词（空格=AND 逻辑，词越多越严，4 词全命中很难）；③ 换同义词。
- 三轮都空才记「数据缺口：未搜到」，**严禁首轮空就当作没数据放弃**。

```bash
# 逆向工程价值链：从需求增量往下钻（默认不加 time_range）
curl -s "http://localhost:4000/search?q=低空经济+产业链+核心部件&format=json&language=zh-CN"
# 定位约束节点的扩张难度
curl -s "http://localhost:4000/search?q=变压器+交付周期+产能紧张&format=json&language=zh-CN"
# 识别控制者份额
curl -s "http://localhost:4000/search?q=InP衬底+国产+市占率+厂商&format=json&language=zh-CN"
```

### 2. 递进式搜索策略（游丝 ≠ 光谱的关键）

光谱是"一次宽泛搜 → 聚类方向"。**游丝是沿价值链逐层向下钻**，每一层的搜索结果决定下一层搜什么。对应下方"投资决策工作流"的 Step3-Step5：

#### 查询分层（三层，越搜越深）

**每层搜不到有效结果→先降关键词数再试，不要直接加 AND 条件加重过滤。**

| 层 | 别名 | 关键词格式 | 搜什么 | 默认不加 time_range |
|----|------|-----------|--------|-------------------|
| **L1 主题+约束** | 需求增量 / 价值链拆解 | `{主题} + 产业链/上游/核心部件/BOM` | 确认钱往哪流、链怎么拆 | ✅ |
| **L2 验证+控制者** | 约束验证 / 控制者识别 | `{节点名} + 交付周期/认证/扩产/良率/市占率/牌照` | 验证扩张慢、找谁控制 | ✅ |
| **L3 错配+映射** | 错配与证伪 / 上市映射 | `{控制者} + 营收占比/市值/研报/替代/扩产` | 判断错配、证伪条件、找A股映射 | ✅（除非找"最近一周新闻"） |

规则：
- **词越少越先跑**：先 2-3 词跑 L1，命中后再加词下钻，不要一开始就 4-5 词 AND。
- `time_range` 默认不加——结构性信息（份额/产能/认证周期）变化慢，不加过滤更可能命中。
- 首轮空按三轮重试：去 time_range → 减词 → 换同义词。三轮都空/弱→降级 data_gap，不许无限追。

```
第1轮｜需求增量    搜「{主题} 需求/订单/政策/资本开支」→ 确认钱往哪流（对应 Step2 需求增量）
   ↓ 用第1轮结果里的终端产品名
第2轮｜价值链拆解   搜「{终端产品} 产业链/BOM/上游/关键部件」→ 逐层拆到第三层（对应 Step3）
   ↓ 用第2轮拆出的可疑约束节点名
第3轮｜约束验证    搜「{候选节点} 交付周期/认证/良率/扩产/稀缺」→ 验证扩张慢、替代难（对应 Step4）
   ↓ 用第3轮确认的约束节点名
第4轮｜控制者识别   搜「{约束节点} 市占率/份额/龙头/厂商/牌照」→ 找谁控制、上市映射（对应 Step5）
   ↓ 用控制者公司名
第5轮｜错配与证伪   搜「{控制者} 营收占比/市值/研报覆盖」+「{节点} 替代/自研/扩产」（对应 Step6-7）
```

**不要预设答案。** 价值链结构、约束节点、控制者都由搜索数据决定，不靠记忆里的旧案例。

⚠️ **来源质量门禁（P0 才能支撑 drilled）**：

| 级别 | 来源 | 能否支撑 drilled | 用法 |
|------|------|:---:|------|
| **P0** | 招股书 / 年报 / 公告 / `.gov.cn` / 行业协会 / 招标文件 | ✅ 最强证据 | 可直接作为控制者/份额/扩产周期的强证据 |
| **P1** | 券商研报 / 机构纪要 / 企业官网 / 专利 | ✅ 可支撑 | 需标注"研报口径"或"公司口径"，最好有 P0 交叉验证 |
| **P2** | 新闻稿 / 垂直媒体 / 付费数据库摘要 | ⚠️ 仅作线索 | 可指引搜索方向，不能单独进结论 |
| **P3** | 自媒体 / 百科 / 股吧 / 聚合站 / 营销稿 | ❌ 不可进结论 | 只能作线索不能作证据；若只有 P3 来源→必须降 data_gap |

规则：
- **只有 P0/P1 来源才能支撑 `drilled`**
- 若某候选的搜索结果 P3 占比 >50% → 强制降为 `data_gap`
- P2 只能做搜索线索，不能作为"控制者是谁"的唯一证据

### 3. 并发编排（主 agent 执行流程）

游丝的并发**不是扫候选池**，而是"一个主题 → 拆出 N 个候选约束节点 → 每个节点派一个子 agent 深挖"，更接近光谱的"N 个方向并行"。

```
用户给主题（行业/赛道/公司）
  ↓ 主agent 第1-2轮搜索（需求增量 + 价值链拆解），把链拆到第三层
  ↓ 主agent 圈出 N 个候选约束节点（物理/时间/牌照/信任/网络/认知 六类）
  ↓ 主agent 给每个节点派一个子agent，带「子agent提示词骨架」+ 该节点的搜索线索
┌────────┬────────┬────────┐
│ 节点1  │ 节点2  │  ...   │ ← 各自做第3-5轮搜索：验证约束强度→识别控制者→错配判断→打分
└────────┴────────┴────────┘
  ↓ 主agent 汇总各节点的15分评分 → 按 S/A/B 排序去重 → 输出游丝判断 → M2
```

> 注：候选节点通常只有 3-8 个（一条价值链的深层约束不会太多），并发数随节点数走，不必凑满 10-15。

### 3+. 递归下钻调度协议

> **三层是最低钻探深度，不是收工条件。** 本协议采用两段式递归：子agent Quick-Hop Scan（最多2层）→ 主agent Chokepoint Audit → 二阶深核。第0-1轮产出的一阶全景图只是起点。主agent必须审核、再派发，直到钻透或证伪。

#### 各轮职责

```
Round 0 — Mainagent Seed
  主agent做需求增量搜索 + 价值链粗拆（只拆图不下结论）
  → 产出：初始链路图 + 候选约束节点列表
  → 派发：每个第一层节点给一个子agent（并发）

Round 1 — Quick-Hop Scan（子agent快扫，非最终裁判）
  子agent内部最多 quick scan 2 层
  → 输出：next-hop candidates（3-6个）+ Quick-Hop 6问标签 + drill_status 初判
  → 不得因为内部搜了2层就直接把所有结论写成最终 S/A

Mainagent Chokepoint Audit（必经门）
  主agent回收所有 Round 1 candidates
  → 按 chokepoint score 选择 1-3 个继续
  → 写 audit 表：candidate | 继续/剔除 | 理由 | Round 2 任务
  → 被选中的 continue 节点必须进入 Round 2

Round 2 — 二阶深核
  新子agent只挖主agent点名的下一层节点
  → 输出：drilled / continue / dead_end / data_gap（四态之一）
  → 只有经过 Mainagent Audit + Round 2 的 drilled，才能作为最终 S/A 游丝
```

#### 每轮主agent审核清单

子agent返回后，主agent必须逐项检查：

- [ ] 子agent是否停在龙头？
- [ ] 是否停在第一层供应商？
- [ ] 是否追满至少三层？
- [ ] 是否有控制者与控制方式？
- [ ] 是否有错配、催化/释放路径、证伪条件？
- [ ] 是否给出 `drill_status`？
- [ ] `drill_status=continue` 是否已进入下一轮派发？（未进入=调度失败）

凡停在龙头/第一层供应商且没有上游依赖分析的，主agent必须判 `continue` 或 `data_gap`，**不得验收为 S/A 级游丝**。

#### 至少追三层

```
终端需求 → 系统/产品/服务
  → 关键部件/关键资质/关键网络节点
  → 底层材料/底层设备/工艺/牌照/标准/信任网络
```

三层不是终点——真正终点是找到深层约束（控制者+控制方式+错配+证伪条件齐全），或证明继续下钻没有更强约束。

#### 递归预算

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 第一轮并发上限 | 30 | 广谱扫描阶段 |
| 第二轮并发上限 | 按 `continue` 节点数 | 只对 S/A+ 或 `continue` 节点派发 |
| 第三轮并发上限 | 按仍为 `continue` 且有明确下钻价值的节点数 | |
| 单条链最大递归层数 | 5 | 超过 5 层必须说明继续下钻价值 |
| 全主题并发子agent上限 | 30 | 跨所有轮次累计 |
| 子agent内部 quick scan 上限 | 2 层 | 超过 2 层必须停止并把候选交回主agent；子agent可建议继续下钻但不能自行无限递归 |

#### 一阶全景图例外

若用户明确只要求"全景报告/产业链概览"，可以停在第一轮。但主agent**必须标注**：
> ⚠️ 一阶全景：未做二阶深挖。S/A+ 节点可在后续任务中进入递归下钻。

#### Quick-Hop 6问（Serenity 启发）

每个 Round 1 next-hop candidate 必须回答以下 6 问：

| # | 问题 | 判别标准 |
|---|------|---------|
| **1. Demand** | 需求增量是否真实？ | 来自政策/订单/capex/招标/客户预算中的哪一种？无证据=弱 |
| **2. BOM** | 处在链条哪一层？ | 终端/模块/子系统/组件/材料/原料/设备/工艺/认证？ |
| **3. Physical** | 扩产/良率/设备/原料是否慢？ | 扩产需>1年？良率有天花板？设备单源？ |
| **4. Monopoly** | 供应商是否集中？ | <3家？CR1/CR3 集中？有没有 second source？ |
| **5. Qualification** | 替代认证/导入需要多久？ | >12个月？需客户/监管审批？切换成本高？ |
| **6. Capture** | 约束能否转化为定价权？ | 有毛利率/长期合同/利润留存的证据？ |

**选点规则**：
- 至少 4 项强，才值得主agent派 Round 2。
- Demand/BOM 不清楚 → 默认 `data_gap`，不得继续硬挖。
- Monopoly/Qualification 弱 → 默认 `dead_end` 或观察，不得评 S/A。

#### 收敛状态 (`drill_status`)

每个子agent完成一轮分析后，**必须**返回以下四态之一：

| 状态 | 含义 | 规则 |
|------|------|------|
| `drilled` | 已钻透 | 找到控制者+控制方式+错配+催化/释放路径+证伪条件齐全 + **已通过 Mainagent Chokepoint Audit + 至少一次 Round 2 二阶深核** → 可评 S/A |
| `continue` | 未钻透，需下一轮 | 必须给出下一轮建议下钻节点（至少1个） |
| `dead_end` | 继续下钻证伪 | 必须说明在哪一层怎么证伪的（商品化/分散/无定价权/无控制者） |
| `data_gap` | 公开资料不足 | 必须列出具体缺口和下一步查证路径（如"需要付费数据库/企业拜访/现场调研"） |

核心规则：
- **只有 `drilled` 才能评 S/A 级。** `continue`/`data_gap` 最多评 B 级并标注"待深挖"。
- `continue` 必须给出下一轮建议下钻节点（≥1个），否则视为子agent未完成任务。
- `dead_end` 也是合法收敛——诚实证明"这个方向没有再往下挖的价值"比硬凑 S 级有价值。
- **最终 S/A 游丝必须满足**：drill_status=drilled + 经历过 Mainagent Chokepoint Audit + 如果来自递归任务，至少有一次 Round 2 二阶深核。未经 Audit + Round 2 的 drilled 最多评 B 级，标"Quick-Hop 初筛·待二阶深核"。

### 4. 子 agent 提示词骨架（主 agent 按节点填充后下发）

主 agent 给每个候选约束节点派子 agent 时，**按以下 7 要素骨架填空**。①③④⑥固定照抄，②⑤⑦按本节点情境填。

```text
【①角色 + 签名第一问】
你是猎犬游丝分析员。只回答一个问题：
```

## 投资决策工作流

### Step 1: 问题分类

| 类型 | 特征 | 动作 |
|------|------|------|
| **行业主题** | 如低空经济、AI电力、创新药、军工电子 | 从需求增量开始拆价值链 |
| **具体公司** | 涉及股票代码、公司名、产品名 | 先定位公司在哪个价值链节点 |
| **框架讨论** | 只问方法论、概念、类比 | 直接解释框架，不做标的判断 |
| **组合分析** | 和光谱、动量、价值等一起用 | 先用对方技能定方向，再用游丝深挖约束 |

**CHECKPOINT**：涉及具体标的、行业、价格、政策、财务或市场份额时，必须获取最新资料后再判断。

### Step 2: 信号采集

按行业选择合适的数据源，优先使用一手信息。

| 信号 | 要查什么 | 常用来源 |
|------|----------|----------|
| **需求增量** | 钱/订单/政策/用户/产能正在流向哪里 | 财报、公告、政策文件、行业协会、招投标 |
| **价值链结构** | 从终端需求到关键投入品的每一层 | 年报、招股书、产业报告、公司官网、专家纪要 |
| **控制者** | 谁控制关键节点、份额、牌照、渠道或标准 | 市占率报告、客户披露、专利、资质目录 |
| **扩张难度** | 扩产周期、认证周期、良率、审批周期、替代成本 | 财报电话会、环评/能评、注册进度、客户认证公告 |
| **市场定价** | 当前市值、收入、利润、覆盖度、资金关注度 | 财报、交易数据、券商研报、机构持仓 |
| **证伪信号** | 什么会让这个节点不再关键 | 技术替代、政策变化、竞争扩产、客户自研 |

### Step 3: 价值链拆解

不要停在第一层供应商。至少向下追三层，直到找到扩张最慢或替代最难的位置。

```text
需求增量 / 风口 / 政策方向
  ↓
终端产品 / 服务 / 项目
  ↓
核心系统 / 渠道 / 交付能力
  ↓
关键部件 / 关键资质 / 关键网络节点
  ↓
底层材料 / 耗材 / 标准 / 数据 / 牌照 / 信任关系
  ↓
游丝：那个“不解决它，整条链就转不快”的深层约束
```

### Step 4: 约束强度评分

给每个候选节点打分，满分 15 分。

| 指标 | 0分 | 1分 | 2分 | 3分 |
|------|----|----|----|----|
| **需求拉动** | 无增量 | 概念性增量 | 订单/政策确认 | 多源信号同时确认 |
| **扩张难度** | 可快速复制 | 需要数月 | 需要1年以上 | 需要多年/牌照/认证/稀缺资源 |
| **替代难度** | 替代很多 | 替代可行 | 替代成本高 | 替代会破坏交付或合规 |
| **控制集中度** | 分散竞争 | CR3较高 | 少数寡头 | 单源/准单源/强网络控制 |
| **认知错配** | 已充分定价 | 部分覆盖 | 市场低估 | 几乎无人关注但链条离不开 |

| 总分 | 判定 |
|------|------|
| **13-15** | S级游丝：优先深挖，可能是核心机会 |
| **10-12** | A级约束：值得跟踪，等待估值或催化 |
| **7-9** | B级节点：存在约束，但可能不够稀缺 |
| **≤6** | 非游丝：更像普通供应商或主题伴随者 |

### Step 5: 控制者识别

找到约束后，必须回答“谁真正控制它”。

| 控制方式 | 要验证的问题 |
|----------|--------------|
| **资产控制** | 是否拥有关键矿、厂、仓、设备、产线、地理位置？ |
| **技术控制** | 是否掌握工艺、专利、良率、know-how？ |
| **资质控制** | 是否拥有牌照、认证、目录、客户准入？ |
| **关系控制** | 是否绑定关键客户、渠道、医院、军方、政府或平台？ |
| **标准控制** | 是否参与行业标准、接口协议、数据格式或生态规则？ |
| **网络控制** | 是否控制节点越多，后来者越难追？ |

注意：控制者不一定是上市公司。可能是非上市主体、集团子公司、地方平台、海外供应商，或上市公司的小业务线。

#### 控制者分层

每个控制者必须按其与控制节点的关系分类。**只有直接控制者才能作为 S/A 级游丝的强证据。**

| 分层 | 定义 | 证据权重 | 示例 |
|------|------|---------|------|
| **直接控制者** | 直接拥有/控制该约束节点（技术/产能/牌照/标准） | ★★★★★ 强证据 | 特变电工控制换流变压器产能、KLA 控制量检测设备 |
| **上游控制者** | 控制该节点的上游关键投入（材料/设备/资质） | ★★★★ 次强证据 | 宝钢/首钢控制特高压的取向硅钢 |
| **替代追赶者** | 正在追赶但尚未达到控制地位 | ★★★ 有限证据 | 天岳先进在追 Wolfspeed 的 SiC 衬底 |
| **间接上市映射** | 不直接控制该节点，而是通过集团/子公司/少数股权关联 | ★★ 弱证据 | A 公司持股 5% 的参股企业控制某节点 |
| **概念噪声** | 被市场打上相关概念标签但无实质控制 | ★ 不可用为证据 | 水务公司被东财打"机器人概念"标签 |

规则：
- 直接控制者 → 可作为 S/A 级游丝的强证据
- 上游控制者 → 标注"上游约束"，可辅助佐证但不可替代直接控制者
- 替代追赶者 → 标注"国产替代窗口"，有效但需注明差距
- 间接上市映射 → 标注"间接关联·非直接控制"，不可作为主证据
- 概念噪声 → 必须降权或剔除，不可出现在 S/A 级判断的证据链中

### Step 6: 错配判断

游丝机会来自“深层重要性”和“市场注意力”之间的落差。

| 错配类型 | 判断方式 |
|----------|----------|
| **价值链错配** | 节点决定交付，但收入/利润占比看起来很小 |
| **市值错配** | 控制者市值远低于被它约束的下游市场空间 |
| **覆盖错配** | 行业报告讨论很多终端，但很少讨论该节点 |
| **周期错配** | 市场看短期利润，但约束价值会在扩产/认证/交付后释放 |
| **叙事错配** | 市场追“卖铲子”，但真正短缺在“给铲子供水/供料/给牌照” |

不要把“便宜”直接等同于“错配”。错配必须由证据链支持。

### Step 7: 证伪条件

每个游丝结论都要写出退出或降级条件。

| 证伪类型 | 典型信号 |
|----------|----------|
| **需求证伪** | 下游订单、政策、预算、用户增长不达预期 |
| **约束证伪** | 新产能快速释放、替代路线成熟、认证周期缩短 |
| **控制证伪** | 客户自研、竞争者切入、份额下降、关键资质失效 |
| **定价证伪** | 约束存在但利润无法留在控制者手里 |
| **估值证伪** | 市场已充分定价，风险回报不再不对称 |

## 从卖铲子到游丝

游丝框架保留“卖铲子”理论，但把它放在价值链层级里，而不是当作终点。

| 层级 | 角色 | 风险 | 特征 |
|------|------|------|------|
| **淘金** | 直接追风口 | 高 | 竞争激烈，叙事最热 |
| **卖铲子** | 给风口卖工具 | 中 | 需求更确定，但容易被看见 |
| **卖水** | 给工具/生产过程提供耗材或服务 | 较低 | 高频复购，现金流更稳定 |
| **游丝** | 控制最深层约束 | 取决于定价权 | 不一定大，但替代最难、扩张最慢 |

核心纪律：

1. 不停在龙头。
2. 不停在第一层供应商。
3. 不把“上游”自动等同于“游丝”。
4. 只有当约束真实、控制清晰、错配存在时，才叫游丝。

---

## 决策启发式

| # | 启发式 | 动作 |
|---|--------|------|
| H-1 | **从需求增量开始** | 先确认钱、订单、政策、用户或产能正在流向哪里 |
| H-2 | **沿价值链向下钻三层** | 终端 → 系统/渠道 → 关键投入 → 深层约束 |
| H-3 | **找扩张最慢的点** | 对比每层扩产、认证、牌照、导入和替代周期 |
| H-4 | **找替代最痛的点** | 如果替换会影响交付、合规、良率或客户信任，权重上调 |
| H-5 | **小环节也可能有大控制权** | 关注财报占比小但链条离不开的节点 |
| H-6 | **控制者优先于概念股** | 先找谁控制约束，再看有没有可投资映射 |
| H-7 | **证伪条件先写清楚** | 每个结论必须能被事实推翻 |
| H-8 | **警惕伪游丝** | 只有稀缺没有定价权、只有热点没有控制权，都不是好游丝 |

---

## 反模式

| 反模式 | 为什么错 |
|--------|----------|
| **把热门行业龙头当游丝** | 龙头常常是需求承接者，不一定控制深层约束 |
| **把所有上游都当游丝** | 上游也可能竞争激烈、无定价权 |
| **只看市占率，不看替代成本** | 高份额但容易替代，不构成强约束 |
| **只看技术壁垒，不看利润留存** | 技术重要不代表股东能赚到钱 |
| **只看题材，不写证伪条件** | 没有证伪条件就无法管理风险 |
| **用旧数据判断当前约束** | 扩产、政策和竞争格局会快速改变 |

### 反模式 → 硬门槛（主agent验收标准）

以下情况**不得验收**为有效游丝产出，必须退回子agent或判 `continue`/`data_gap`：

| 硬门槛 | 后果 |
|--------|------|
| **只列龙头，没有上游依赖** | 退回，判 `continue` |
| **只列第一层供应商，没有拆到部件/材料/设备/资质/标准/信任网络** | 退回，判 `continue` |
| **把热门公司等同于游丝** | 退回，要求重新按六分法判断 |
| **把市占率高直接等同于控制权** | 退回，要求补充替代成本和定价权分析 |
| **找到控制者但不写错配、催化/释放路径、证伪条件** | 降级 ≤B，标注"证据不全" |
| **一阶全景图完整但 S级节点没有递归下钻** | 标"一阶全景·二阶待深挖"，不可标"已完成" |

## 风险框架

| 风险 | 处理方式 |
|------|----------|
| **约束被绕开** | 持续跟踪替代路线、客户自研和新供应商 |
| **约束存在但不赚钱** | 检查议价权、成本传导、合同结构 |
| **市场已充分定价** | 错配不足时降级为观察 |
| **政策改变约束结构** | 对牌照、准入、补贴、出口管制保持再评估 |
| **公开信息不足** | 标注证据缺口，不把推测写成结论 |
| **A股交易制度差异** | 考虑涨跌停、流动性、主题拥挤和信息倒灌 |

## Serenity 方法的位置

原 AI/半导体版本来自 Serenity 供应链瓶颈方法论。新版游丝保留其精华，但不再把行业边界锁死在 AI/半导体。

可继承的部分：

1. 从资本开支和需求增量开始。
2. 做多层 BOM / 价值链逆向工程。
3. 找物理扩张慢、供应集中、替代困难的节点。
4. 用市值、覆盖度、机构滞后判断错配。
5. 用论题证伪而不是目标价作为退出条件。

需要扩展的部分：

1. 物理约束只是六类约束之一。
2. 价值链不只包括 BOM，也包括牌照、渠道、数据、信任、标准和网络。
3. A股、产业政策和本土供应链要单独校准。
4. 任何行业都要重新采集最新证据，不可套用旧案例。

详细 Serenity 调研材料见 `references/research/`，仅在需要追溯原始方法论或 AI/半导体案例时读取。

## 数据缺口清单

输出结论前检查以下缺口：

| 缺口 | 问题 |
|------|------|
| **需求证据** | 是否只有叙事，没有订单/预算/政策/用户数据？ |
| **价值链地图** | 是否只拆到第一层，没有继续向下追？ |
| **控制者证据** | 是否知道节点重要，却不知道谁控制？ |
| **扩张周期** | 是否知道短缺，却不知道短缺会持续多久？ |
| **替代路径** | 是否检查了客户自研、技术替代和竞争扩产？ |
| **定价权** | 是否证明控制者能把约束转化为利润？ |
| **估值状态** | 是否区分“好公司”和“好价格”？ |
