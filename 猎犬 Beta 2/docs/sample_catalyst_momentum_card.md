## 对比演示：取交集 vs 时序触发

### 取交集法（等动量也进强势池才算）

```
催化池(10只) ∩ 动量强势池(假设2只: 600063, 600060)
= 命中2只 → 600063 皖维高新, 600060 海信视像
```

**问题**：
1. 600063 皖维高新：20d已涨+12%，追高有风险
2. 600060 海信视像：处于回调阶段，入场点不易把握
3. **漏掉600026 中远海能**——催化刚发、动量刚启动的最佳窗口
4. **漏掉全部7只催化事件标的**——市场尚未定价，但恰是预期差最大的早期机会

### 时序触发法（先催化已现，再动量确认阶段）

```
Step 1: 催化池(10只)全部入选 → 先发已现
Step 2: 动量阶段分类 →
  - Group 1(动量已进强势池): 600063, 600060 → 双确认，但入场需谨慎
  - Group 2(动量刚启动✅): 600026 → 最佳时序命中点
  - Group 3(动量未起/监控): 600031,600075,600072,600028,600048,600037,600055 → 先发标记，等待后发
```

**优势**：
1. **不遗漏**：10只催化标的全部纳入视野
2. **区分阶段**：明确每个标的处于动量周期的哪个环节
3. **优先Group 2**：600026的"催化已现+动量刚起"是最优风险收益比入场点
4. **监控Group 3**：7只催化标的持续监控，一旦动量改善即时介入

### 直观对比表

| 对比维度 | 机械取交集 | 时序触发 |
|---------|-----------|---------|
| 总捕获数 | 2只（600063, 600060） | 10只（全部催化标的） |
| 最佳买点（600026） | ❌ 漏掉 | ✅ 捕获 |
| 已涨超15%的标的 | ✅ 抓到（但已晚） | ✅ 标记阶段 |
| 催化先发等待动量的标的 | ❌ 全部漏掉 | ✅ 标记监控 |
| 时间错位识别 | ❌ 无此概念 | ✅ 核心机制 |
| 预期差评价 | ❌ 只看当下 | ✅ 区分已定价/未定价 |

## 触发场景验证

### "催化先发→动量加速段"（时序触发版）

**结论**：✅ **成立，且与取交集有本质差异**

本批数据证实：

1. **时序机制是实质性不同的筛选框架**：取交集看"两个池子当下重叠"，时序触发看"时间先后+阶段匹配"。在50只样本中，两者输出的标的重叠仅2只（600063, 600060），差异达8只。

2. **Group 2（600026 中远海能）是最佳命中点**：催化已发、动量刚启动、尚未price in，这是时序机制独有的捕获区间，交集法从根本上漏掉。

3. **Group 3（7只）提供了"先发已现、后发待起"的持续监控源**：这是取交集无法提供的价值——取交集直接剔除它们（不在强势池不给看），时序机制保留它们作为"等待动量触发的观察标的"。

4. **本场景的高频触发环境**：在市场震荡或下跌末期（如当前市场）→ 催化事件先于市场反应发生→ 动量随后启动——这种时间差在弱势市场中最常见，也是时序配方最有效的时候。

## 与取交集配方的使用建议

| 机制 | 适用场景 | 不适用场景 |
|------|---------|-----------|
| 取交集（如资金+催化事件爆发） | 两维度**都已确认**、需要双重验证 | 时间错位明显、一方先发一方后起的场景 |
| 时序触发（本配方） | 催化先发、动量刚起的时间窗口 | 需要双重确认（不想承担时间差风险）的场景 |

**建议搭配使用**：
1. 先跑时序配方，捕获"催化已现+动量待起"的早期标的（Group 2+3）
2. 等动量确认后，Group 3中升级的标的自然进入取交集范畴
3. 时序配方是**提前布局工具**，取交集是**确认工具**——两者互补而非替代

## 已知局限

1. **样本局限**：50只300/600前缀样本中，催化事件集中在周期性行业（航运、机械、化工）。Group 2只有600026一例——全市场扫描可能发现更多"催化已发+动量刚起"的标的。

2. **动量阶段基于客观数据**：本卡对10只催化标的的动量阶段分类基于价格数据和RS计算，未经动量子agent独立判断。实际运行时应有动量子agent读动量SKILL做"强势池/观察池/不入池"的判定。

3. **时效性**：价格数据基于最近交易日，动量状态可能随行情快速变化。600026中远海能的MA20突破可能在下一交易日被跌破（今天收于MA5之下）。

4. **RS计算基准**：相对强度基于CSI 300大盘指数，缺乏细分行业指数对比。行业相对强度需走get_concept_blocks定性。
