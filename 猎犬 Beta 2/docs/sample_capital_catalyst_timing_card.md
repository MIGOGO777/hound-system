## 核心命题：时序触发识别"谁在催化前就埋伏了"

Recipe B 与 Task 3（资金+催化取交集）共享相同的数据源——资金池和催化池。**但时序机制问的不是"两个池子当下重叠多少"，而是"资金吸筹在先、催化事件在后——这种因果顺序是否成立？"** 后者多了一个时间维度，能区分"先知先觉"和"随大流"。

## 对比演示：取交集 vs 时序触发

### 取交集法（静态双重确认）

```
资金池(14只) ∩ 催化池(10只)
= 3只 → 600037 歌华有线, 600072 中船科技, 600075 新疆天业
```

✅ 正确捕获了资金+催化同时成立的3只标的。但这3只恰好也都是"资金先于催化"的时序命中点，取交集在这个特例中没有额外损失。

**但取交集的两个固有问题并未解决**：
1. **不知道先后顺序**：600038 中直股份若进入催化池（新闻标"业绩预警"也算催化），取交集也会捕获它，但它实际上是负面催化（业绩-81%）——取交集不区分正面/负面催化
2. **忽略7只资金先埋伏标的**：这些标的中出现催化时，取交集要等到催化池更新才能捕获，没有前瞻性

### 时序触发法（先资金后催化）

```
Step 1: 资金池(14只) → 先发已现
Step 2: 逐只检查催化事件：
  - 催化已触发+正面 ✅ 命中（3只）
  - 催化微弱/未确认 ⏳ 观察点（3只）
  - 催化未至 👁️ 监控中（7只）
  - 负面催化/需排除 ❌ 降级（1只）
```

**时序机制额外提供的价值**：
1. **因果验证**：确认资金先于催化布局（600072筹码-13.83%透露了先手信息）
2. **催化过滤器**：过滤掉600038的负面催化（取交集不会自动区分正负面）
3. **监控队列**：保留7只"资金先埋伏+催化未至"标的，等待催化信号触发
4. **预期差判断**：催化未至的标的中，600066宇通客车筹码集中-16.57%+底部机构建仓——这种极端筹码变化暗示"机构知道一些市场不知道的事"，可能催化在途

## 与机械取交集的本质差异总结

本卡与Task 3（资金+催化取交集）使用同一批数据，但方法论的根本差异在于：

| 差异项 | Task 3 取交集 | 本卡 时序触发 |
|--------|--------------|-------------|
| **问题** | "哪些股票现在既有资金又有催化？" | "哪些股票资金先埋伏了，然后催化来了？" |
| **池序** | 先跑两池→再取重叠 | 先发池→逐只检查后发条件 |
| **时间感** | 无时间维度（静态快照） | 有时间维度（先发→后发顺序） |
| **漏判风险** | 一方先发的标的全部漏掉 | 先发已现的保留，等后发条件 |
| **负面过滤** | 不区分正负面催化 | 负面催化主动排除 |
| **前瞻性** | 无（必须两池都有才算） | 有先发池监控，催化来即升级 |

**关键结论**：
- 在本批数据中，取交集和时序触发在"当前时点"的命中数一致（3只），但时序机制**多捕获了7只监控标的**和**过滤了1只负面催化标的**——这些是取交集无法提供的增量价值。
- 时序机制的核心不是"找到更多命中点"，而是**建立因果关系**和**提供前瞻性监控**。在催化事件密集出现的市场阶段（财报季、政策密集期），监控队列中的标的可能快速转化为命中。

## 已知局限

1. **时间精度受限**：筹码变化数据（get_holder_change）是季度级别，无法精确判断资金吸筹和催化公告的先后顺序。600072的筹码-13.83%可能在催化公告前就已发生，也可能在公告后——现有数据精度不足以绝对确定。

2. **资金信号的滞后性**：get_fund_flow的资金流数据为最新交易日，不能回溯历史资金流变化。时序机制对"资金先于催化"的判断主要依赖筹码数据（滞后）和定性推断。

3. **催化事件识别依赖新闻源**：新闻头条可能漏掉重要公告，尤其是小市值标的。600066宇通客车的催化事件可能未被新闻头条覆盖。

4. **负面催化的自动识别**：本卡手动识别了600038中直股份的负面催化。实际运行中，需要催化子agent在判断时标注"正面/负面/中性"——当前催化SKILL尚无此字段，建议补充。

5. **样本偏差**：同Recipe A，50只600xxx传统行业样本，未覆盖创业板和科创板。
