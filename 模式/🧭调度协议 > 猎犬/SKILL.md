# 猎犬 · 调度协议

## §0 角色与边界
- 主agent = 调度者 + 审核者，**不亲自做认知判断**（判断永远在子agent读lens SKILL时发生）。
- 不碰策略阈值（那是各lens SKILL的活）。Python只取数+客观质检，绝不算分。
- 数据边界：fetcher路线在对话跑python；光谱/游丝走 curl SearXNG(localhost:4000)。

## §1 意图识别（路由表）
| 用户输入 | 路由到 |
|---------|--------|
| 单技能名/单维度（"用价值扫一下"） | §3 单技能扫描 |
| 两技能/组合词（"底部反转""政策+供应链"） | §7 查配方库 → §4 |
| 给主题深挖（"低空经济产业链"） | §7 光谱→游丝串联 |
| "全市场扫描" | 默认多技能并行 |
| 模糊 | 反问澄清（意图/时间范围/范围） |

## §2 候选池准备
- fetcher路线：扫描前主agent跑一次 get_universe → ~4000只，当日缓存复用。
  调用：cd "猎犬 Beta 2" && python3 -c "from hound_system.data.fetcher import HoundFetcher; from hound_system.universe.screener import UniverseScreener; print(UniverseScreener().get_universe(HoundFetcher()))"
- SearXNG路线（光谱/游丝）：不跑screener，从主题搜起。

## §3 单技能扫描流程
读对应lens SKILL「数据入口协议」3段 → 预取 → 客观初筛 → 切批 → 并发派子agent → 回收(§6)。

## §4 组合配方流程
串联：A产出 → 喂B输入；共振：A、B各自独扫 → 取交集。具体配方见§7。

## §5 子agent派发规约
- 提示词 = lens SKILL的7要素骨架，主agent现场填②本批任务⑤输出契约⑦反投机。
- 真并发派发（不为旧模型阉割）。预取数据塞进提示词；深挖数据子agent自取。

## §6 议题卡回收与审核
格式校验(11字段不留空) → 去重(同标的多来源合并共振线索) → 排序(置信度×信号强度) → 反编造审计(缺口如实标注Builder#12) → 交付清单给用户/M2。
- 输出存档：主agent调用 `ReportConfig().save(cards, recipe="配方名")`，报告自动存入 `/mnt/redbox/金色报告/{当天日期}/`。

## §7 组合配方库

### §7.1 配方表达规范（三机制母版）

> 配方不是一种形态两种字段，而是**三种合流机制**（green-coco 体检结论：原"共振9配方"实际混了三种逻辑，强套一个母版会把缺陷复制9份）。每个配方挂到对应机制母版下，只写差异条目。

**机制① 取交集型（真双维印证）**：A、B 各自独扫，取同 code 交集。
- 母版流程：主agent 跑 get_universe → 预取初判数据(节制，深挖留子agent) → 派 A、B 两组子agent各读自己SKILL判断 → 取两池交集 → 交集标的共振线索互填、双证据链。空集是正常结果(按§7.3空集处置)。
- 适用前提：A、B 两池**同类可比**(都是个股级)、**两维度独立**(不是同义重复)。
- 母版字段：配方名 / 参与技能(对等) / 触发场景 / 两池各扫什么 / 为何1+1>2 / 合流特殊点。
- **金标准样板 = §7.3 资金+价值**(已实战验证)。

**机制② 时序触发型（一先一后，看时间错位）**：一个镜头先发生(潜伏/催化在前)，触发另一个，关注的是**时间差**不是静态交集。
- 母版流程：主agent 先用"先发镜头"找出已触发标的 → 再看"后发镜头"是否刚启动(而非已走完) → 命中"先发已现、后发将起"的时间窗。
- ⚠️ **不能机械取交集**：若等两池都满足才算命中，最佳买点(催化刚发、动量未起)恰好落在交集外，会系统性漏掉(green-coco 关键纠错)。
- 母版字段：配方名 / 先发镜头→后发镜头 / 触发场景 / 时间窗定义 / 漏判防范。

**机制③ 映射串联型（主题级→个股级跨类落地）**：上游主题镜头(光谱/游丝，走SearXNG产出方向/产业链)→下游个股镜头(价值/动量/资金/催化，走fetcher在方向内选票)。
- 母版流程：上游产出"方向名/产业链节点" → **映射环**(把方向翻译成个股池：板块成分/概念归属) → 下游个股镜头在该池内判断 → 产出议题卡。
- ⚠️ **映射环是关键且易漏**：主题级产出的是"方向名"，个股镜头吃的是"个股池"，中间必须有"方向→所属个股"的翻译步骤(用 get_concept_blocks 等)，否则两端接不上(green-coco 指出 §7.2 也缺此环)。
- 母版字段：配方名 / 上游→下游 / 触发场景 / 映射环怎么做 / 交接契约。
- **金标准样板 = §7.2 光谱→游丝**(已实测，但属"主题→产业链研究"分支；"主题→个股选股"分支见 §7.4 主干道)。

### §7.2 样板①：光谱→游丝（串联，已实测）
- 配方名：光谱→游丝
- 形态：串联（A产出喂B输入）
- 参与技能：光谱(上游) → 游丝(下游)
- 触发场景：用户想"从政策方向挖到产业链卡点"
- 数据流：光谱输出"热门方向名" → 作为游丝第1轮搜索的 {主题} 入参
- 交接契约：光谱产出方向名+理由 → 游丝用方向名做需求增量搜索。
  ⚠️ 光谱第1轮(需求增量)天然顶替游丝第1轮，上游交棒省一轮（已实测）。
  ⚠️ 游丝子agent继承SearXNG重试规则（默认不加time_range、首轮空三轮重试）。
- 产出：游丝判断卡（S/A/B级深层约束节点，15分制）

#### 递归下钻升级（2026-06-30）

光谱只交付方向名与政策理由，游丝第一轮产出一阶全景图后，主agent必须挑 S/A+ 节点进入递归下钻：

1. **光谱交棒**：方向名 + 政策理由 → 游丝第1轮需求增量搜索。
2. **游丝第一轮**：产出价值链全景 + 各节点 `drill_status`。
3. **主agent审核**：对每个 S/A+ 节点逐项检查审核清单（是否停在龙头/是否只停在第一层/是否追满三层/是否有控制者+错配+证伪条件）。
4. **递归下钻**：对 `drill_status=continue` 的节点，再派新一轮子agent继续下钻。
5. **收敛**：所有节点 `drilled`/`dead_end`/`data_gap` 后，合并输出最终游丝判断。

⚠️ 若用户明确要"全景报告"，可以停在一阶，但**必须标注**：
> ⚠️ 一阶全景：未做二阶深挖。S/A+ 节点可在后续任务中进入递归下钻。

### §7.2+ 游丝递归派发母版（2026-06-30）

> 游丝不是一次派完就写综述。主agent必须回收、审核、再派发。本母版统领所有含游丝的组合配方（光谱→游丝、催化→游丝、动量→游丝、游丝→个股）。

#### 六阶段流程（2026-06-30 mini-fix 升级）

```
第一阶段：Mainagent Seed（主agent第0轮搜索）
  主agent做需求增量搜索 + 价值链粗拆（只拆图不下结论）
  → 产出：初始链路图 + 候选约束节点列表
  → 派发：每个第一层节点给一个子agent（并发，最多30）

第二阶段：Quick-Hop Scan（子agent快扫，非最终裁判）
  子agent内部最多 quick scan 2 层
  → 输出：3-6 个 next-hop candidates + Quick-Hop 6问标签 + drill_status 初判
  → 不得因为内部搜了2层就直接把所有结论写成最终 S/A

第三阶段：Mainagent Chokepoint Audit（必经门）
  主agent回收所有 Round 1 candidates
  → 按 chokepoint score 选择 1-3 个继续
  → 写 audit 表：candidate | 继续/剔除 | 6问强项 | 风险/缺口 | Round 2 任务
  → 被选中的 continue 节点必须进入 Round 2

	  **🆕 证据审计字段**（每个 candidate 必须填写）：
	  - source_tier：P0 / P1 / P2 / P3 / no_source —— 本轮最高来源级别
	  - search_quality：strong / medium / weak / noisy / no_source
	  - trusted_hits：P0/P1 来源中信息一致的结果数
	  - weak_hits：P2/P3 来源的结果数
	  - stop_reason：若被剔除非继续，写清是"证据弱/噪音高/已达停止线/无上市映射/公开信息耗尽"

	  **🚫 硬规则**：
	  - 只有 source_tier=P0/P1 且 search_quality=strong/medium 的 candidate 才能进入 Round 2
	  - weak/noisy/no_source → 一律优先转 data_gap 或 dead_end
	  - P3 为主(>50%)的 candidate → 强制 data_gap
	  - 连续 2 轮 search_quality=weak/noisy → 主agent必须停止对该节点的搜索，改判 data_gap

第四阶段：二阶深核（Round 2）
  新子agent只挖主agent点名的下一层节点
  → 输出：drilled / continue / dead_end / data_gap（四态之一）
  → 只有经过 Mainagent Audit + Round 2 的 drilled，才能作为最终 S/A 游丝

第五阶段：控制者上市映射
  对每个 drilled 节点的每个控制者，主agent补全球上市映射
  （A股→fetcher；美股/港股→global adapter；其他→Yahoo/SearXNG fallback；未上市标unlisted）

第六阶段：游丝→个股深核（可选衔接）
  产出 A 股短名单后，可无缝衔接 价值/资金/动量/催化 子agent深核判断
```

#### 主agent审核规则

游丝子agent返回后，主agent必须逐项检查（9 条，由游丝 SKILL 3+.递归下钻调度协议定义）：

1. 子agent是否停在龙头？
2. 是否停在第一层供应商？
3. 是否追满至少三层？
4. 是否有控制者与控制方式？
5. 是否有错配、催化/释放路径、证伪条件？
6. 是否给出 `drill_status`？
7. `drill_status=continue` 是否已进入下一轮派发？
8. 报告是否包含 Mainagent Chokepoint Audit 表？（没有 = 不能声称完成递归下钻）
9. 是否完成了至少一次 Round 2 二阶深核？（没有 = 最多标"Quick-Hop 初筛完成"，不能标"递归下钻完成"）

- 第 1-5 条任一不满足 → 判 `continue` 或退货给子agent补充
- `continue` 节点未进入下一轮派发 → **调度失败，主agent失责**
- 一阶全景图完整但没有 S 级节点进入递归下钻 → 标"一阶全景·二阶待深挖"，**不可标"已完成"**

#### 验收硬门槛

| 缺少项 | 后果 |
|--------|------|
| 报告没有 Mainagent Chokepoint Audit 表 | **不能声称完成递归下钻** |
| 没有 Round 2 二阶深核 | 最多标 **"Quick-Hop 初筛完成"**，不能标"递归下钻完成" |
| S/A 级节点未经过 Audit + Round 2 | 降级为 B，标"Quick-Hop 初筛·待二阶深核" |
| 子agent内部搜了>2层但主agent没有 Round 2 再派发 | **调度失败**，退回重做 |
| 存在 continue 节点但既未进入 Round 2、也未降级 data_gap/dead_end/移除 | **调度未收口**，不得声称"递归完成" |
| Round 2 后仍有 continue 且未给补钻优先级排序 | 继续派发或降级，不得以"后续再挖"搪塞 |

#### 补钻优先级（continue 节点的排序规则）

Round 2 预算有限时，不是所有 `continue` 都自动进入。主agent必须给每个 `continue` 节点打 `drill_priority`：

| drill_priority | 判定依据 | 派发规则 |
|---------------|---------|---------|
| **P0** | 卡脖子强度高 + 证据强 + 有明确 A 股映射 | ✅ 必须优先派 Round 2 |
| **P1** | 卡脖子但证据部分弱 / 证据强但映射不确定 | ✅ 预算允许时派发 |
| **P2** | 约束存在但证据弱 / 映射模糊 | ⚠️ 视预算和 search_quality 决定 |
| **P3** | 纯概念噪声 / 无映射 / 证据耗尽 | ❌ 可直接降级 data_gap 或排到队列末尾 |

每个 `continue` 节点必须标注 `drill_priority` + `priority_reason`（一行，为什么这个优先级）。

**规则**：
- `continue` 不是自动进 Round 2——必须先过补钻优先级排序
- Round 2 预算上限 = 3 个节点；超出的 P2/P3 直接降级或入"后续队列"
- 若所有 continue 都是 P2/P3 → 主agent应停止递归，标注"无高优先级继续节点，递归收口"

**五段式交付契约**：递归型游丝最终报告必须按五段式输出——产业链全景图 → Quick-Hop候选卡点 → Mainagent Chokepoint Audit → 二阶深核结果 → 可投资映射。缺任一段，不能标"递归下钻完成"；最多标"过程数据不完整"。五段式详细格式见游丝 SKILL「递归型游丝最终报告格式」节。

#### 递归预算

| 参数 | 默认值 |
|------|--------|
| 第一轮并发上限 | 30 |
| 第二轮并发上限 | 按 continue 节点数（只派 S/A+ 或 continue） |
| 第三轮并发上限 | 按仍有明确下钻价值的 continue 节点数 |
| 单条链最大递归层数 | 5（超过 5 层须说明继续价值） |
| 全主题累计并发上限 | 30 |

#### 停止条件

主agent在以下情况停止递归：

| 条件 | 含义 |
|------|------|
| 所有节点 `drilled` | 正常完成——所有约束已钻透 |
| 所有剩余节点 `dead_end` | 正常完成——诚实证伪，无更强约束 |
| 所有剩余节点 `data_gap` | 正常完成——公开信息已耗尽，标注缺口 |
| 达到 5 层上限 | 标注"达到最大递归层数"，说明继续下钻价值留给人工 |
| 连续 2 轮无新 `drilled` 产出 | 标注"边际信息递减，停止递归"，防止浪费搜索预算 |
| 子agent内部 quick scan 已达 2 层上限 | 停止内部扫描，将 candidates 交主agent Audit，**不得自行继续** |
| 连续 2 轮 search_quality=weak/noisy | 标注"证据已耗尽"，停止搜索，判 data_gap（不得继续消耗搜索预算） |
| 首轮空 → 三轮重试后仍空或仍 weak | 判 data_gap，标注"SearXNG 未返回有效信息" |
| P3 来源占比 >50% 且无 P0/P1 交叉验证 | 判 data_gap，标注"来源质量不足" |

#### 控制者分层与输出字段

**分层**（由游丝子agent在分析时完成）：直接控制者 / 上游控制者 / 替代追赶者 / 间接上市映射 / 概念噪声

**上市映射字段**（由主agent在第三阶段补全，全部7个必填）：
- `country`：控制者所在国家
- `listing_status`：listed / unlisted / delisted / subsidiary / unknown
- `market`：US / HK / CN / JP / KR / DE / TW / UNKNOWN
- `ticker`：股票代码（无则留空标"无上市映射"）
- `currency`：USD / HKD / CNY / JPY / KRW / EUR / TWD / UNKNOWN
- `price`：最新价（取不到留空标"data_gap"）
- `price_source`：global-stock-data:sina / tencent / eastmoney / yahoo / searxng
- `as_of`：价格日期
- `coverage_status`：covered / fallback / not_covered / data_gap
- `mapping_type`：direct / parent / subsidiary / proxy / no_mapping

**缺失处理**：任何字段取不到都标注原因，**不得编造**。

#### 游丝→个股衔接（可选）

游丝递归完成后若产出 A 股控制者短名单，主agent可无缝衔接游丝→价值/资金/动量/催化深核：

- 游丝→价值 = 卡脖子公司 + 是否低估 = 被低估的隐形冠军
- 游丝→资金 = 卡脖子公司 + 资金是否进场 = 约束被市场定价

走游丝→个股深核子型（不经过映射环——游丝产出已是个股，直接逐个深判）。

### §7.3 样板②：资金+价值=底部反转（共振，已实战验证 2026-06-28）
- 配方名：资金+价值=底部反转
- 形态：共振（各自独扫取交集）
- 参与技能：资金、价值（对等无先后）
- 触发场景：找"被低估且资金正在进场"的票
- 各自扫描（**判断归子agent，主agent只取数+派发，不许自己量人**）：
  - 价值池：主agent跑 get_universe → **预取只给"够做第一判断"的数据**(get_valuation估值+价格位置) → 派价值子agent组（读价值SKILL）判断"哪些算低估" → 子agent产出低估候选议题卡
  - 资金池：主agent跑 get_universe → **预取只给初判数据**(get_capital_evidence的价格位置/量比) → 派资金子agent组（读资金SKILL）判断"哪些存在资金行为代理证据" → 子agent产出流入候选议题卡
  - ⚠️ **预取节制（M3踩坑#2教训）**：深挖数据(get_financials财报/get_closes走势/get_reports研报、get_capital_evidence证据包)**留给子agent按需自取**，主agent不要一次喂饱。实测预取过度会让子agent偷懒不深挖、反而漏判（如资金预取截断部分序列，子agent自取get_capital_evidence才能看全60日量价/位置/融资/大宗/筹码全貌）。提示词②须明确写"你需自行补取：get_capital_evidence(量价/位置/融资/大宗/筹码/市场/概念全证据包)"。
  - ⚠️ 主agent**不许自己定"什么叫低估/什么叫流入"**（不写 PE<15、super_net>0 这类阈值），那是子agent读SKILL的认知判断（§0铁律）。
- 合流规则：取两个子agent池的标的交集（同 code 命中）
- 共振增强：命中交集的标的，主agent在两张子agent议题卡的"共振线索"字段互相标注（价值卡注"资金同步流入确认"，资金卡注"估值偏低确认"）；置信度由**双重证据链支撑**，不套用固定加分公式
- 产出：合并议题卡（来源技能="价值+资金"，双重证据链）。
- **空集处置**：交集为空是正常结果（两镜头对小样本认知不重叠很常见），不是失败。主agent按序处理：① 若样本偏小(<100只) → 扩大样本至约200只重试；② 仍空 → 向用户/M2 如实报告"当前样本未发现资金+价值共振标的"，**严禁为凑数硬凑交集或放宽判断**（Builder#12）。

#### 催化→动量共识协议（双动量子agent，2026-06-30 新增）

在`催化→动量=加速段`实战运行时，动量侧强制执行以下共识规则：

- 实战运行时，动量侧优先派 2 个动量子agent，二者都读 `技能包/📈技术 > 动量/SKILL.md`。
- 两个子agent必须独立判断：`趋势启动 / 趋势已走完 / 未启动监控 / 无法判断`。
- 主agent只做共识汇总：
  - `consensus=agree_starting`：两者均判趋势启动，可作为时序命中候选。
  - `consensus=agree_not_starting`：两者均判未启动/已走完，进入监控或排除。
  - `consensus=disagree`：不得入池，只能标"待人工/第三agent复核"。
- 主agent不得把自己的 MA/RS 计算覆盖子agent结论。

> 💡 背景：2026-06-29 单agent复核揭示 600026 中远海能被误判为"动量刚启动"实为"趋势耗尽"，证明单agent动量判断有盲区。双agent共识降低单点误判率。

#### ⭐ 选股主干道：光谱→个股（机制③专节，最高频）

> green-coco 发现的最大遗漏：21种镜头组合原仅列13个，缺的8个全是光谱/游丝一端。其中 `光谱→个股` 是猎犬**最自然的用户需求**——"政策吹哪个方向 → 这方向里哪些票低估/有资金/强势"——却一个没列(§7.2只收了偏研究的光谱→游丝)。本节补上这条主干道。

- 配方名：光谱→个股
- 形态：机制③ 映射串联
- 上游→下游：光谱(出政策方向) → 价值/动量/资金/催化 任一或多个(在方向内选票)
- 触发场景：用户问"政策利好哪个方向，里面挑哪些票" / "跟着政策风口选股"
- **流程(三段)**：
  1. **光谱出方向**：主agent 派光谱子agent(走SearXNG)→ 产出受政策支持的方向名+象限+理由(如"AI算力·🟢要支持")。
  2. **映射环(关键)**：把方向名翻译成个股池——主agent 对候选池股票调 `get_concept_blocks` 查概念归属，筛出归属该方向的个股，得到"方向内候选池"。⚠️ 这一步不可省，否则下游个股镜头没有输入。

     ⚠️ **映射环后加纯度分级（2026-06-29 新增）**：
     - 映射环筛出"方向内候选池"后，主agent对每只调 `classify_concept_purity(concept_tags, keywords)` 打 purity=high|medium|low
     - high/medium → 下沉下游镜头（价值/资金/动量/催化）
     - low → 默认标"落地存疑·概念噪声"，仅保留背景，不浪费子agent深判预算
     - 纯度分级是客观标签归类，不是选股判断（§0铁律）
     - concept_tags + industry → high/medium/low；行业识别仅作降噪辅助，不替代下游价值/资金/动量/催化子agent判断。

  3. **方向内选票**：在"方向内候选池"上跑选定的个股镜头(§3单技能流程)——价值判低估/资金判流入/动量判强势/催化判事件。下游镜头**仍是子agent读SKILL判断，不写阈值**(§0)。
- 交接契约：光谱产出"方向名"(SearXNG侧) → 映射环转"个股池"(fetcher侧) → 个股镜头判断。**跨了SearXNG→fetcher两条数据路线，映射环是唯一桥**。
- 可叠加：方向内若同时跑两个个股镜头(如价值+资金)，则在方向内候选池上套机制①取交集 → 即"政策方向×底部反转"复合配方。
- 产出：议题卡(来源技能="光谱→X"，证据链含政策方向理由+个股镜头判断)。
- 状态：✅已实战验证(2026-06-28) — 猎犬 Beta 2/docs/sample_spectrum_stock_card.md。

##### 主干道的4个下游实例（光谱→价值/资金/催化/动量）

主干道下游镜头可换，每个实例是同一条路换个"选票视角"，**机制相同(三段映射串联)，已验证一个即推广**：

| 实例 | 下游问的问题 | 投资含义 |
|------|------------|---------|
| 光谱→价值 | 政策方向内，哪些票低估？ | 政策支持下的安全边际(政策托估值容忍度) — ✅主干道Task1已跑此实例 |
| **光谱→资金** ⭐ | 政策方向内，哪些票资金真在进？ | **给政策风口做真伪测谎**：政策是国家意志，资金是真金投票。同向=国家队+市场合力(最强)；背离=预期差埋伏点。✅已验证(2026-06-29，背离逻辑坐实) |
| 光谱→催化 | 政策方向内，哪些票有催化落地？ | 政策落地的具体抓手(从"方向对"到"事件兑现") |
| 光谱→动量 | 政策方向内，哪些票已经启动？ | 政策方向里市场最先承认的那批(方向+时机) |

> 💡 **背离警报(光谱→资金 专属逻辑)**：政策🟢支持但资金未进 = 两种可能——①市场还没反应(左侧机会，标"政策埋伏·待资金确认") ②市场不信政策能落地(标"政策落地存疑·待验证")。**分歧本身是信号**，子agent须判断属哪种，不可只报"无交集"。这正是光谱单用的盲区(政策喊了没人买)，资金来补。

##### 🆕 游丝→个股：串联深核变体（不走映射环，区别于上面的映射串联）

> ⚠️ **与"光谱→个股"的本质区别**：光谱产出"方向名"(宽)，须经映射环转个股池再扫；**游丝产出的本就是"控制者公司"(已是个股，且极少，通常3-8个)**，无需映射环、无需扫池——直接对这几个精确标的派下游镜头**逐个深核**。这是"窄而深"，不是"宽而扫"。

- 配方名：游丝→个股(串联深核)
- 形态：机制③ 映射串联的**深核子型**(上游给少数精确点 → 下游逐个深判，跳过映射环)
- 上游→下游：游丝(挖出产业链卡脖子控制者，已是个股) → 价值/资金(对这几家逐个深核)
- **流程(两段，无映射环)**：
  1. **游丝出控制者**：派游丝子agent(走SearXNG递进搜索)→ 产出价值链深层约束节点的控制者标的(如"InP衬底→某上市公司")+ 约束强度评分。
  2. **个股深核**：对游丝给出的少数控制者标的，派下游镜头子agent**逐个深判**(不扫池，标的就这几个)。
- 两个实例：
  - **游丝→价值** = 卡脖子公司 + 是否低估 = 🎯被低估的隐形冠军(护城河深+市场没给溢价，最理想)。回答游丝盲区"瓶颈真实但现在贵不贵"。
  - **游丝→资金** = 卡脖子公司 + 资金是否进场 = 📈约束开始被市场定价。回答游丝盲区"瓶颈真实但有没有人买"。
- 触发场景：用户问"XX产业链卡在哪、那家公司现在能不能买" / 先做产业链研究再落到买点。
- ⚠️ **不可套主干道映射环**：游丝输出已是个股，硬塞 get_concept_blocks 反查概念是多此一举且会引入噪声。
- 产出：议题卡(来源技能="游丝→X"，证据链含产业链约束理由+个股镜头判断)。
- 状态：✅已验证(2026-06-29) —— 游丝→价值实战通过：AI算力链10控制者→价值3入池(中际旭创/新易盛/沪电股份)；游丝→资金实战通过：同批10控制者→资金0入池、3观察，深核子型确认无映射环、直接深判有效。
